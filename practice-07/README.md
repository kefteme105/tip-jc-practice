## Компоненты и состояние

`App` владеет `tasks`, `filters`, `editingId`. Видимые задачи, статистика и редактируемая запись вычисляются при рендере. `TaskForm` владеет `draft`, `errors` и сообщением результата; поля управляются через value/onChange.

`TaskFilters` передаёт родителю новый объект фильтров. `TaskItem` сообщает id через обработчики, `TaskList` связывает карточки и категории, `TaskStats` получает готовую статистику. Стабильный ключ карточки равен id. Ключ формы `editingId ?? 'new'` создаёт новый черновик при переключении записи.

Форма нормализует название и categoryId. Только синхронный ответ `true` от onSave очищает создание; `false` сохраняет черновик и показывает сообщение. Подтверждение удаления находится вне updater. Назначение id — чистое вычисление по актуальному массиву внутри функционального обновления, без внешнего счётчика.

## Контрольные вопросы

1. JSX — синтаксис описания React-элементов, который преобразуется сборщиком в вызовы JavaScript. Это не строка HTML.
2. Props приходят от родителя; состояние хранится внутри владельца и меняется setter-функцией.
3. Изменение обычной переменной не просит React перерисовать компонент и не сохраняет значение между рендерами как useState.
4. Функциональное обновление нужно, когда новое значение зависит от предыдущего, особенно при нескольких обновлениях подряд.
5. Копирование массива не копирует объекты внутри. Изменение объекта затронет прежнее состояние; заменяется и массив, и изменённая запись.
6. key связывает компонент с записью. После удаления индексы сдвигаются, а id остаются стабильными.
7. Производные значения вычисляются из одного источника данных; дополнительное состояние могло бы рассинхронизироваться.
8. Дочерний компонент вызывает переданный callback с id или новым значением.
9. Управляемое поле получает value из состояния и меняет его через onChange.
10. Значение select — строка, а categoryId в модели — число. Number и проверка категории предотвращают частично числовые значения.
11. Изменение key размонтирует старую форму и создаёт новую с начальными полями.
12. React может повторять updater в StrictMode; диалог и другие побочные эффекты не должны повторяться вместе с ним.
13. При пустом общем массиве total равен 0; при отсутствии совпадений общий total может быть положительным.
14. npm test проверяет предметные функции, но не внешний вид, клавиатуру и реальный браузер.
15. В ПР8 источник данных и обработчики заменяются API, добавляются эффект, loading/error, отмена чтения и асинхронное сохранение.
