## Цель и результат

Реализован собственный сервер чтения задач и категорий на Node.js/Express. Сохранён контракт GET учебного API из предыдущих практик, добавлены строгая валидация query и id, нормализованные фильтры, структурированные ошибки, HEAD, OPTIONS, CORS и ответы 405. ## Реализация

- validation проверяет весь id регулярным выражением и Number.isSafeInteger; разбирает URLSearchParams без потери дубликатов.
- task-service выполняет чистую фильтрацию через И и поиск по id; порядок исходного массива сохраняется.
- store создаёт отдельные копии начальных данных для каждого экземпляра приложения.
- routes связывает HTTP-пути с валидацией и store, формирует data/meta и ошибки.
- app устанавливает общие заголовки, OPTIONS, маршруты, обработчик неизвестного пути и обработчик ошибок.
- server проверяет порт и открывает сетевое соединение. Фабрика app сама порт не занимает.

Строка false преобразуется явно через сравнение с true: Boolean('false') дал бы неверное true. Неизвестные и повторяющиеся параметры отклоняются до фильтрации. Пустой q допустим; прочие пустые значения фильтров недопустимы. Неизвестный положительный categoryId даёт пустую выборку, а не ошибку.

## Контракт

| Метод и путь | Результат |
|---|---|
| GET /api/health | 200, data.status: ok |
| GET /api/categories | 200, data и meta.total: 3 |
| GET /api/tasks | 200, data и meta с количеством выборки и нормализованными filters |
| GET /api/tasks/:id | 200 и data либо ошибка id/отсутствия |
| HEAD для тех же путей | Статус и заголовки GET без тела |
| OPTIONS для любого пути | 204 и CORS без тела |
| Остальные методы известных путей | 405 METHOD_NOT_ALLOWED, Allow: GET, HEAD, OPTIONS |

Пример успешного ответа:

```json
{"data":{"id":4,"title":"Подготовить модель задач","completed":false,"priority":"high","categoryId":2}}
```

Примеры ошибок:

```json
{"error":{"code":"INVALID_ID","message":"Некорректный id."}}
{"error":{"code":"TASK_NOT_FOUND","message":"Задача не найдена.","details":{"id":2}}}
{"error":{"code":"METHOD_NOT_ALLOWED","message":"Разрешены GET, HEAD и OPTIONS."}}
```

Их статусы соответственно 400, 404 и 405. Неизвестный маршрут получает 404 ROUTE_NOT_FOUND; внутреннее исключение — 500 INTERNAL_ERROR без служебного текста. meta.total считает только отфильтрованные записи.

В ПР9 сервер предоставляет чтение. POST/PATCH/DELETE и debug/reset из ПР8 здесь намеренно недоступны по контракту задания; добавление записи и серверной валидации тела относится к ПР10.

## Исправленный дефект

Симптом: если фильтровать completed обычной проверкой истинности, строка false ведёт себя как true. Причина: непустая строка в JavaScript истинна. Исправление: принимать только строки true/false, затем явно преобразовывать в boolean и сравнивать с null для отсутствующего фильтра. Повторная проверка: модульные и HTTP-тесты completed=false и совместного фильтра возвращают ожидаемые id 4 и 34.

## Контрольные вопросы

1. В Node.js нет DOM/window браузера, зато доступны серверные модули, файловая система и открытие HTTP-порта.
2. Обработчик выбирается по HTTP-методу и пути. Query передаёт условия выбранному обработчику.
3. req.params содержит параметры пути, например id. Query находится после ? и содержит фильтры.
4. Строка false истинна как непустая строка, поэтому требуется явное сравнение.
5. parseInt принимает начало строки 4abc. Проверка всей записи и safe integer исключает частичный разбор и потерю точности.
6. Пустая выборка является успешным результатом списка; конкретная отсутствующая запись не найдена.
7. TASK_NOT_FOUND означает отсутствие записи в известном ресурсе, ROUTE_NOT_FOUND — отсутствие маршрута.
8. При 405 маршрут существует, но метод запрещён. Allow сообщает разрешённые методы; 404 означает отсутствие ресурса или маршрута.
9. meta.total равен длине полученной выборки.
10. OPTIONS должен завершиться раньше маршрутов, а обработчики 404 и ошибок должны идти после них.
11. Express узнаёт обработчик ошибок по сигнатуре error, req, res, next.
12. createApp позволяет тестировать несколько независимых приложений на свободных портах без побочного запуска сервера при импорте.
13. Клиенту отправляется безопасное сообщение и код INTERNAL_ERROR без стека и внутренней информации.
14. CORS регулирует чтение ответа браузером с другого origin и не подтверждает личность пользователя.
15. В ПР10 нужны маршруты создания/обновления/удаления, разбор и проверка JSON, назначение id, изменение store и расширение списка методов CORS/Allow.
