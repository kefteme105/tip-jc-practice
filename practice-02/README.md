## 4. Модель данных и функции

Модель задачи имеет четыре поля:

id
title
completed
priority

id — положительное безопасное целое число. В пределах одного списка идентификаторы должны быть уникальными.

title — строка длиной от 1 до 100 символов после удаления пробелов по краям с помощью trim().

completed — логическое значение. При создании новой задачи всегда устанавливается false.

priority — одно из трёх значений:

low
medium
high

По умолчанию используется "medium".

Назначение файлов

data.js содержит исходные данные.

task-service.js содержит функции работы с задачами и не выполняет вывод в терминал.

main.js отвечает за последовательность действий и вывод результатов.

checks.js проверяет соответствие функций заданным контрактам.

Реализованные функции
createTask

Создаёт новую задачу после проверки id, title и priority.

При успехе:

{ ok: true, task: ... }

При ошибке:

{ ok: false, error: "..." }

Каждый успешный вызов создаёт новый объект задачи.

findTaskById

Использует find и строгое сравнение ===.

Возвращает найденный объект либо undefined.

getPendingTasks

Использует filter.

Возвращает новый массив задач, у которых:

completed === false
getTaskTitles

Использует map.

Возвращает новый массив строк с названиями задач.

getTaskStats

Возвращает:

{
  total,
  completed,
  pending,
  progress
}

При пустом массиве:

{
  total: 0,
  completed: 0,
  pending: 0,
  progress: 0
}

Процент прогресса хранится числом без предварительного округления.

addTask

Создаёт задачу через createTask, проверяет уникальность id и добавляет её в конец нового массива.

При успехе:

{ ok: true, tasks: newArray }

При ошибке:

{ ok: false, error: "..." }
setTaskCompleted

Изменяет только поле completed выбранной задачи.

Для изменения используется map и поверхностное копирование объекта.

renameTask

Проверяет и нормализует название, затем создаёт новый объект изменяемой задачи.

Остальные поля задачи сохраняются.

removeTask

Удаляет задачу через filter.


**Почему id не равен индексу:** Индекс показывает текущее положение элемента в массиве.id является постоянным идентификатором самой задачи и не зависит от её положения в массиве..  
**Почему getTaskStats возвращает число, а не строку с процентом:** getTaskStats возвращает progress числом, поскольку это результат расчёта, который можно использовать в дальнейших вычислениях..
